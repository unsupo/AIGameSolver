# Plan 11: Intro Breakout & Menu Exhaustion Fix [COMPLETED]

## Analysis
The logs indicated that the AutoGamePlayer agent was caught in a feedback loop between the Menu Exhaustion logic and the LLM Meta-Reasoner fallback, failing to progress past the title screen and naming screens.

### 1. Why it was stuck: The "B-Spam" Trap
- **Menu Exhaustion Trigger:** The AgenticBrain tracked how long a menu was open without progress. After 10 steps, it triggered "Menu Exhaustion" and forced a B press to "exit the interface".
- **The Reset Loop:** In Pokémon Red, the title screen, "New Game" menu, and Naming Screen are identified as UI/Intro phases. If the agent took too long to decide, the system forced B, which reset the title animation or backed out of the "New Game" selection, or deleted characters on the naming screen.
- **Fallback Inefficiency:** When a loop was detected, the system routed to the LLM Meta-Reasoner, which often defaulted to a random internal brain fallback.

## Implementation Details

### 1. Robust Intro & Naming Protection [DONE]
- **Increased Threshold:** In `src/autogameplayer/brains/agentic/brain.py`, the menu exhaustion threshold was increased to **50 steps** specifically for the title screen, "New Game" menu, and Naming Screen (detected via map IDs 0/38 or OCR: "POKEMON", "NEW GAME", "NAME", "ED", "A B C").
- **Forced Progress:** When exhaustion is reached on these critical screens, the brain now forces a **START** or **A** press instead of a B press, ensuring the sequence progresses forward instead of resetting.

### 2. Context-Aware Fallback [DONE]
- **Intro Priority:** The `fallback_action` in `AgenticBrain` now prioritizes **START** or **A** when the `map_id` is 0 or None (intro phase), instead of picking purely at random.

### 3. Planner & Skills Prioritization [DONE]
- **Skill Injection:** Modified `src/autogameplayer/brains/agentic/planner.py` to strongly suggest the use of the `SKILL_SKIP_INTRO` macro when an intro screen is detected.
- **Naming Macro:** Seeded a new `SKILL_NAMING` macro (`A -> A -> A -> START -> A`) in `src/autogameplayer/core/optimizer.py` to help the agent bypass the character name selection grid.
- **Dialogue Clearer:** Updated `PlannerAgent` to prioritize `SKILL_CONFIRM` when the Odometer detects zero movement over multiple frames during the intro, ensuring the agent clears text blocks.

### 4. Interface Breakout Adjustment [DONE]
- **B-Spam Prevention:** Adjusted the escalation logic in `AgenticBrain`. It no longer defaults to B-spam if the current screen contains "POKEMON" or "NEW GAME", preventing the agent from backing out of the starting sequence.

### 5. High-Frequency Intro A-Spam [DONE]
- **A-Stutter Fix:** Implemented a high-frequency A-press mechanism in `AgenticBrain` specifically for the intro phase. If `is_dialogue` is true during the intro, the brain now forces an A-press every 2 steps to speed up text clearing.

### 6. Robust Reflection Parsing [DONE]
- **JSON Extraction:** Enhanced `extract_json_from_llm_response` in `src/autogameplayer/utils/llm.py` to robustly handle markdown code blocks and noisy conversational text from local models (like gemma3:4b).

## Verification
- **Dry Run:** Confirmed that the `BrainSolverAdapter` and the updated `AgenticBrain` logic initialize correctly.
- **Manual Observation:** The agent now reliably bypasses the naming sequence and reaches the overworld by executing the `SKILL_NAMING` or prioritized START inputs.
